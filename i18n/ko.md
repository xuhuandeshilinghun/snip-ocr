# SnipOCR
> C++17 / Qt6 기반 Windows용 고성능 스크린샷, 데스크톱 스티커 및 오프라인 OCR 유틸리티

SnipOCR은 Windows 10 / 11 x64용 오픈소스 올인원 데스크톱 유틸리티입니다. 고성능 스크린샷, 데스크톱 플로팅 스티커 미리보기, 이미지 주석, 다국어 오프라인 OCR 인식, 지연 반복 스크린샷, 자동 업데이트 기능을 통합합니다.

**UI 지원 언어: 중국어(간체), 중국어(번체), 영어, 일본어, 한국어, 독일어, 프랑스어, 러시아어. 위 모든 언어의 OCR 텍스트 인식을 지원합니다.**

모든 이미지 처리와 텍스트 인식은 **로컬 기기에서 실행되며 스크린샷이 클라우드로 업로드되지 않아 프라이버시가 보호됩니다.**
사무 자료 추출, 독해·번역 보조, 웹 문서 텍스트 추출, 개발자 에셋 캡처, 교육 데모 스크린샷 주석 등 다양한 상황에서 활용할 수 있습니다.

네이티브 Windows API와 Qt6로 개발되었습니다. 고‑DPI 다중 모니터 환경을 지원하고 밝은/어두운 테마를 제공하며 완전한 국제화 다국어 UI를 갖추고 시스템 트레이에서 백그라운드 실행할 수 있습니다.

## 기능
### 📷 스크린샷 모듈
- **전역 핫키 스크린샷**: Windows 저수준 키보드 훅 `WH_KEYBOARD_LL`을 구현합니다. 활성 창 포커스와 상관없이 핫키 한 번으로 스크린샷을 호출합니다.
- **자유 영역 선택**: 마우스 드래그로 선택 사각형을 그리고 8개 크기 조절 제어점을 제공합니다. 화살표 키 미세 조정: 1픽셀 단위 이동, `Shift + 화살표 키`는 10픽셀 이동으로 정밀 픽셀 선택이 가능합니다.
- **창 스냅**: Snipaste에서 영감을 받았습니다. 선택 영역 가장자리가 창 테두리에 가까워지면 자동으로 붙습니다(기본 임계값 8픽셀). 전체 창을 빠르게 캡처합니다.
- **정확한 창 및 컨트롤 감지**: `WindowFromPoint` + `RealChildWindowFromPoint`를 사용해 버튼, 입력 상자, 툴바 등 하위 컨트롤을 감지하고 컨트롤 영역을 직접 선택할 수 있습니다.
- **DWM 실제 창 경계 획득**: `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`를 호출해 창 그림자를 제외하고 실제 렌더링 크기를 가져옵니다.
- **픽셀 돋보기**: 캡처 모드에서 오버레이 돋보기를 표시합니다. RGB / HEX 색상 값, 화면 좌표를 보여주며 색상 형식 전환을 지원해 색상 추출과 픽셀 검사에 유용합니다.
- **선택 영역 크기 라벨**: 둥근 파란색 배경의 `W × H` 크기 라벨을 선택 영역 근처에 표시합니다. 글자 색은 밝은/어두운 테마에 자동으로 적응합니다.
- **스크린샷 툴바**: 영역 캡처 후 하단 툴바가 나타납니다. 스티커 고정, OCR 인식, QR코드 인식, 이미지 복사, PNG 저장, 취소를 지원합니다.

### 🖼️ 데스크톱 스티커 & 주석
- **데스크톱 플로팅 스티커**: 캡처한 스크린샷을 원래 위치에 직접 고정합니다(Snipaste 스타일). DPR 디바이스 픽셀 비율을 완전 지원해 고해상도 디스플레이에서 흐려지지 않습니다.
- **완전한 주석 툴킷**: 오른쪽 클릭으로 드로잉 툴바를 엽니다. 선택, 펜, 화살표, 사각형, 타원, 강조, 모자이크, 텍스트 메모, 지우개.
- **이미지 변환**: 스티커는 20%‑500% 크기 조절을 지원하며 90도 시계/반시계 회전, 수평·수평 뒤집기를 제공합니다. 모든 연산은 원본 물리 해상도 기준으로 동작해 화질 손실이 없습니다.
- **주석 굽기 내보내기**: 그린 주석을 원본 이미지에 합성하고 원본 해상도를 유지한 PNG로 내보냅니다.
- **화면 색상 선택기 패널**: 독자적으로 구현한 색상 선택기로 화면의 어떤 픽셀 색이든 추출할 수 있으며 다국어 UI와 호환됩니다.
- **스티커 창 그림자 토글**: 스티커 창 그림자를 켜고 끌 수 있으며 Windows11 둥근 창 비주얼 스타일에 맞춥니다.
- **스티커 그룹 관리**: 여러 스티커 그룹(기본 그룹 + 사용자 정의 그룹)을 지원합니다. 그룹 전환 시 현재 그룹 스티커는 숨기고 다른 그룹의 스티커를 복원합니다.
- **스크린샷 히스토리 영구 저장**: 원본 스크린샷은 로컬 `history` 폴더에 PNG로 저장됩니다. 스티커 위치, 크기, 주석 상태는 `.sp1` 파일에 저장되며 XOR+Base64로 가벼운 난독화 처리됩니다(강력한 암호화가 아니며 실수 수정 방지 목적).
- **재시작 시 스티커 자동 복원**: 앱 재실행 시 이전 스티커 위치, 크기, 그룹 설정을 자동으로 복원합니다.

### 🔍 오프라인 OCR 텍스트 인식
- **다중 모델 병렬 로딩**: 여러 인식 모델을 동시에 불러올 수 있습니다. 중영 혼합 텍스트, 한국어, 러시아 키릴 문자, 라틴 문자를 지원합니다.
- **자동 언어 감지**: 이미지 내 문자 비율을 분석해 해당 OCR 모델로 자동 전환합니다. 수동으로 언어를 고를 필요가 없습니다.
- **ONNX Runtime CPU 추론**: CPU만으로 동작합니다. **독립 그래픽카드가 필요하지 않으며** 일반 노트북에서 실행 가능합니다.
- **논블로킹 백그라운드 스레드**: OCR 작업은 독립 QThread에서 실행되므로 인식 중 UI가 멈추지 않습니다.
- **인식 결과 대화상자**: 편집 가능한 OCR 출력 창입니다. 한 클릭으로 클립보드 복사, 텍스트 파일 저장을 지원합니다.

### ⏱️ 지연 스크린샷
- **지연·반복 캡처**: 1‑10초 지연을 설정하고 반복 캡처 횟수를 지정해 일괄 자동 저장합니다.
- **시스템 토스트 알림**: 캡처 시퀀스 완료 시 Windows 네이티브 팝업 알림이 나타납니다. 저장 경로와 캡처 개수를 보여주고 클릭하면 경로를 복사합니다.

### 🔄 자동 업데이트 시스템
- **버전 확인**: 앱 시작 시 자동 버전 검사, 설정 패널에서 수동 확인도 가능합니다.
- **델타 업데이트 메커니즘**: 기준 버전 기반으로 전체 패키지와 차분 패치 파일을 생성합니다. 변경된 파일만 다운로드해 다운로드 크기를 줄입니다.
- **이중 다운로드 소스**: 중국 본토 사용자는 Gitee, 해외 사용자는 GitHub Releases를 사용해 네트워크 환경 차이를 해결합니다.
- **독립 업데이터 바이너리**: `updater.exe`는 순수 Win32 API + minizip로 구현되었고 Qt 의존성이 없습니다.
- **설정·사용자 데이터 보존**: 업데이트 과정에서 `.config_settings.json` 설정 파일을 백업합니다. 업데이트 완료 후 핫키, 테마, 스티커 그룹 설정을 복원합니다.
- **업데이트 재시작 워크플로우**: 업데이트 완료 후 `ShellExecuteExW`로 새 실행 파일을 호출하고 `--restart` 인수를 넘겨 단일 인스턴스 뮤텍스를 건너뛰어 깔끔하게 재시작합니다.

### ⚙️ 시스템 통합
- **시스템 트레이 백그라운드 서비스**: 트레이로 최소화. 오른쪽 클릭 메뉴: 스크린샷, OCR, 지연 캡처, 스티커 그룹, 히스토리 지우기, 환경설정, 앱 재시작, 종료.
- **앱 국제화**: 간체 중국어 `zh_CN`, 영어 `en_US` UI가 내장되어 있습니다. 런타임에서 언어 전환이 가능하며 Qt 기본 대화상자도 현지화됩니다.
- **밝기·어둡기 테마 적응**: 시스템 따라가기 혹은 수동 전환. 오버레이 마스크, 메뉴 구분선, 창 그림자가 테마에 맞춰집니다.
- **단일 인스턴스 뮤텍스**: 전역 Mutex로 앱 중복 실행을 막습니다. 업데이트 재시작 시 특수 인수로 뮤텍스 검사를 생략합니다.
- **UTF‑8 중국어 경로 호환**: Windows 환경에서 중국어 UTF‑8 경로일 때 Qt 네이티브 API가 빈 값을 반환하는 버그를 회피합니다.

## 다운로드 및 설치
1. [Releases](https://github.com/xuhuandeshilinghun/snip‑ocr/releases) 에서 최신 릴리즈를 받으세요: `SnipOCR‑<version>‑win64.zip`
2. 아무 로컬 폴더에 압축을 풉니다. 설치 프로그램이 필요 없는 포터블 소프트웨어입니다.
3. 별도 OCR 모델 아카이브를 다운로드한 뒤 프로그램 내부 `model/` 폴더에 압축 해제합니다.
4. `SnipOCR.exe` 를 실행합니다.

> **필수 시스템 요구사항: Windows 10 / Windows 11 x64**
> OCR 모델 파일 크기가 크기 때문에 메인 프로그램 압축파일에 포함하지 않습니다.
> `C:\Windows`, `Program Files` 등 시스템 보호 폴더에 압축을 풀면 권한 읽기‑쓰기 문제가 발생하므로 권장하지 않습니다.

## 기술 스택
- 언어: C++17
- GUI 프레임워크: Qt 6.5.3+
- 빌드 시스템: CMake 3.20+ / MSVC
- OCR 추론: ONNX Runtime 1.18.1 CPU
- 이미지 처리: OpenCV 4.x
- JSON 파싱: nlohmann/json
- Zip 압축·해제: minizip
- Windows 시스템 인터페이스: Win32 API, DWM, 저수준 키보드 훅
- 컴파일러: MSVC2019 / MSVC2022

## 프라이버시 및 보안 안내
1. 스크린샷 처리, 스티커 렌더링, OCR 인식은 전부 로컬에서 실행됩니다. **소프트웨어는 스크린샷이나 인식 텍스트를 자동으로 인터넷에 업로드하지 않습니다.**
2. 자동 업데이트 기능은 버전 검증과 업데이트 패키지 다운로드 목적으로만 GitHub / Gitee 서버에 연결합니다.
3. `history` 폴더 안 원본 스크린샷은 평문 PNG로 저장됩니다. 비밀번호, 신분증 등 민감한 내용을 캡처했다면 히스토리 폴더를 직접 정리하세요.
4. `.sp1`, `index.dat` 파일은 단순 XOR+base64 난독화일 뿐 **안전한 암호화가 아닙니다. 고도의 기밀 데이터를 저장하지 마세요.**
5. 설정에서 스크린샷 히스토리 저장 기능을 끌 수 있습니다.

## 알려진 제한 사항
- 현재 Windows 10 / 11 x64 만 지원하며 Linux, macOS는 지원하지 않습니다.
- OCR은 CPU 연산 기반이므로 인식 속도는 CPU 성능에 따라 달라집니다.
- OCR 모델 파일이 크므로 수동으로 다운로드하고 배치해야 합니다.
- 혼합‑DPI 다중 모니터 환경은 실제 사용 테스트를 권장합니다. 일부 특수 하드웨어 환경에서 호환 문제가 나타날 수 있습니다.

| 그 외 구버전 | 전체 패키지(1.0.0 기준 버전과의 차이 연산) |
| 미설치 상태 | **먼저 V1.0.0 기준 버전을 설치해야 합니다** |


> ⚠️ `build_release_1.0.0`은 전역 기준 디렉터리입니다. **단 한 번만 생성하고 영구적으로 보관하십시오. 삭제하거나 수정하지 마십시오.** 이후 모든 델타 업데이트는 이 기준 디렉터리에 의존합니다.

### make_release.py 스크립트 예시

```
# 1.【한 번만 실행】기준 버전 1.0.0 생성
python tools/make_release.py --version 1.0.0 --no-build

# 2.1.0.1 릴리즈(기준은 1.0.0 고정, 이전 버전 build_release_1.0.0과 비교)
python tools/make_release.py --version 1.0.1 --make-update --old build_release_1.0.0 --base-dir build_release_1.0.0 --no-build

# 3.1.0.2 릴리즈(기준은 1.0.0 고정, 이전 버전 build_release_1.0.1과 비교)
python tools/make_release.py --version 1.0.2 --make-update --old build_release_1.0.1 --base-dir build_release_1.0.0 --no-build

# 4.1.0.3 릴리즈(기준은 1.0.0 고정, 이전 버전 build_release_1.0.2과 비교)
python tools/make_release.py --version 1.0.3 --make-update --old build_release_1.0.2 --base-dir build_release_1.0.0 --no-build

# 자주 사용하는 명령어
# 전체 작업 흐름: 컴파일 빌드 + 릴리즈 산출물 수집
python tools/make_release.py --version 1.0.1

# 빌드 실행 + 전체 패키지·델타 업데이트 패키지 생성
python tools/make_release.py --version 1.0.1 --make-update --old build_release_1.0.0

# 바이너리가 이미 컴파일 완료됨, 패키징만 수행하고 빌드 단계 건너뛰기
python tools/make_release.py --version 1.0.1 --no-build

# 업데이트 로그와 강제 업데이트 플래그를 활성화한 뒤 업데이트 패키지 생성
python tools/make_release.py --version 1.0.1 --make-update --old build_release_1.0.0 --update-log "1.UI 최적화\n2.알려진 문제 수정" --force-update
```

### 매개변수 간략 참조

- `--version x.x.x`: 대상 릴리즈 버전 번호 지정
- `--no-build`: C++ 컴파일을 건너뛰고 패키징만 수행(바이너리가 이미 빌드되었을 때 사용)
- `--make-update`: 델타 패키지 생성을 활성화하며 전체 패키지와 델타 패치를 모두 출력
- `--old <dir>`: 이전 공식 릴리즈 디렉터리, 파일 비교를 통해 델타 패치를 생성할 때 사용
- `--base-dir <dir>`: 전역 기준 디렉터리, 항상 `build_release_1.0.0`로 지정
- `--update-log`: 해당 버전의 릴리즈 노트, 줄바꿈에는 `\n`을 사용
- `--force-update`: 강제 업데이트 플래그 활성화, 클라이언트에서 업그레이드를 강제 실행
 
> 빌드 결과물은 `build_release_<version>` 하위에 출력됩니다. 폴더 내 zip 아카이브를 GitHub Releases에 업로드하십시오.
