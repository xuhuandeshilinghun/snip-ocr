# SnipOCR
> C++17 / Qt6 で開発された Windows 向け高性能スクリーンショット、デスクトップステッカー、オフラインOCRユーティリティ

SnipOCR は Windows 10 / 11 x64 向けのオープンソース統合デスクトップツールです。高性能スクリーンショット、デスクトップ浮遊ステッカープレビュー、画像注釈、多言語オフラインOCR認識、遅延ループスクリーンショット、自動アップデート機能を備えています。

**UI対応言語：簡体字中国語、繁体字中国語、英語、日本語、韓国語、ドイツ語、フランス語、ロシア語。上記すべての言語のOCR文字認識に対応します。**

すべての画像処理と文字認識は**ローカルデバイス上で実行され、スクリーンショットがクラウドへアップロードされることはなくプライバシーを保護します。**
オフィス資料の抽出、読解・翻訳支援、ウェブドキュメントからの文字取得、開発者向け素材キャプチャ、教育デモ向けスクリーンショット注釈など多様な場面で活用できます。

ネイティブWindows APIとQt6を使用して開発。高DPIマルチモニタ環境に対応し、ライト/ダークテーマを搭載、完全な国際化多言語UIを備え、システムトレイからバックグラウンド実行可能です。

## 機能
### 📷 スクリーンショットモジュール
- **グローバルホットキースクリーンショット**：Windows低レベルキーボードフック `WH_KEYBOARD_LL` を実装。アクティブウィンドウのフォーカスに関わらずホットキー一つでスクリーンショットを起動。
- **自由な領域選択**：マウスドラッグで選択枠を描画、8つのリサイズ制御点を搭載。矢印キーによる微調整：1ステップ1ピクセル、`Shift + 矢印キー` で10ピクセル移動、精密なピクセル選択が可能。
- **ウィンドウスナップ**：Snipasteを参考。選択枠の端がウィンドウ境界に近づくと自動吸着（デフォルト閾値8ピクセル）、ウィンドウ全体を素早くキャプチャ。
- **高精度ウィンドウ・コントロール検出**：`WindowFromPoint` + `RealChildWindowFromPoint` によりボタン、入力ボックス、ツールバーなど子コントロールを検出、直接コントロール領域を選択可能。
- **DWM実ウィンドウ境界取得**：`DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` を呼び出し、ウィンドウのドロップシャドウを除外し実際の描画サイズを取得。
- **ピクセル拡大鏡**：キャプチャモードでオーバーレイ拡大鏡を表示。RGB / HEXカラー値、画面座標を表示。カラーフォーマット切り替えに対応、ピッカーやピクセル確認に便利。
- **選択サイズラベル**：角丸青背景の `W × H` サイズラベルを選択枠付近に表示。文字色はライト/ダークテーマに自動適応。
- **スクリーンショットツールバー**：領域キャプチャ後下部にツールバーが表示。ステッカー貼り付け、OCR認識、QRコード認識、画像コピー、PNG保存、キャンセルに対応。

### 🖼️ デスクトップステッカー & 注釈
- **デスクトップ浮遊ステッカー**：キャプチャした画像を元の位置に直接貼り付け（Snipaste風）。DPRデバイスピクセル比に完全対応、高解像度ディスプレイでもぼやけない。
- **完全な注釈ツールキット**：右クリックで描画ツールバーを開く：選択、ペン、矢印、矩形、楕円、ハイライト、モザイク、テキスト注釈、消しゴム。
- **画像変形機能**：ステッカーは20%‑500%の拡大縮小に対応；90度時計回り/反時計回り回転、水平・垂直反転。すべて元画像の物理解像度で処理され画質が劣化しません。
- **注釈焼き付け出力**：描画した注釈を元画像に合成し、元解像度を保持したPNGを出力。
- **画面カラーピッカーパネル**：独自実装のカラーピッカー。画面上任意のピクセルから色を取得、多言語UIに対応。
- **ステッカーウィンドウシャドウ切替**：ステッカーウィンドウの影のオンオフ可能。Windows11の角丸ビジュアルに適合。
- **ステッカーグループ管理**：複数グループ（デフォルト＋カスタム）に対応。グループ切替で現在のグループを非表示、別グループのステッカーを復元。
- **スクリーンショット履歴永続保存**：元画像はローカルの`history`フォルダにPNGで保存。ステッカー位置・拡大縮小・注釈状態は`.sp1`ファイルに保存。XOR+Base64による簡易難読化（強力な暗号化ではなく、誤編集防止目的）。
- **再起動時ステッカー自動復元**：アプリ再起動後、前回のステッカー位置、倍率、グループ状態を自動復元。

### 🔍 オフラインOCR文字認識
- **複数モデル並列読み込み**：複数認識モデルを同時ロード可能。中日英混在、韓国語、ロシア語キリル文字、ラテン文字に対応。
- **自動言語判定**：画像内の文字割合を解析し、対応するOCRモデルへ自動切替。手動で言語を選択する必要なし。
- **ONNX Runtime CPU推論**：CPUのみで動作。**独立GPU不要**、一般的なノートPCで実行可能。
- **UIをブロックしないバックグラウンドスレッド**：OCR処理は独立したQThreadで実行、認識中もUIがフリーズしません。
- **認識結果ダイアログ**：編集可能なOCR出力ウィンドウ。ワンクリックでクリップボードにコピー、テキストファイルとして保存可能。

### ⏱️ 遅延スクリーンショット
- **遅延・ループキャプチャ**：1‑10秒の遅延設定、ループキャプチャ枚数を指定し一括自動保存。
- **システムトースト通知**：キャプチャ完了時Windowsネイティブ通知を表示。保存先パスと枚数を表示、クリックでパスをコピー。

### 🔄 自動アップデートシステム
- **バージョン確認**：起動時自動バージョンチェック。設定画面から手動確認も可能。
- **差分アップデート機構**：基準バージョンから完全パッケージと差分パッチを生成。変更ファイルのみダウンロードしサイズを削減。
- **デュアルダウンロードソース**：中国本土ユーザーはGitee、海外ユーザーはGitHub Releasesを使用、ネットワーク差異に対応。
- **独立アップデータ実行ファイル**：`updater.exe` は素のWin32 API＋minizipで作成、Qt依存なし。
- **設定・ユーザーデータ保持**：アップデート時に`.config_settings.json`をバックアップ。更新後にホットキー、テーマ、ステッカーグループ設定を復元。
- **アップデート再起動処理**：更新完了後`ShellExecuteExW`で新バイナリを起動、`--restart`引数によりインスタンス排他ロックを回避し正常再起動。

### ⚙️ システム統合
- **システムトレイ常駐**：トレイに最小化。右クリックメニュー：スクリーンショット、OCR、遅延キャプチャ、ステッカーグループ、履歴クリア、設定、再起動、終了。
- **アプリ多言語対応**：簡体字中国語`zh_CN`、英語`en_US`を内蔵。実行中に言語切替、Qt標準ダイアログもローカライズ。
- **ライト/ダークテーマ適応**：システム追従または手動切替。オーバーレイ、メニュー区切り線、ウィンドウシャドウがテーマに追従。
- **シングルインスタンス排他ロック**：グローバルMutexで多重起動を防止。アップデート再起動時は引数でロック判定をスキップ。
- **UTF‑8中国語パス対応**：Windows上中国語UTF‑8パスでQtAPIが空を返す不具合に対応。

## ダウンロードとインストール
1. [Releases](https://github.com/xuhuandeshilinghun/snip‑ocr/releases) から最新版を取得：`SnipOCR‑<version>‑win64.zip`
2. 任意のローカルフォルダに解凍。インストーラ不要のポータブルソフトウェア。
3. OCRモデルアーカイブを別途ダウンロードし、プログラム内`model/`フォルダへ解凍。
4. `SnipOCR.exe`を実行。

> **必須環境：Windows 10 / Windows 11 x64**
> OCRモデルはサイズが大きいためメインパッケージに同梱されません。
> `C:\Windows`や`Program Files`などシステム保護フォルダへの展開は権限問題が発生するため推奨しません。

## 技術スタック
- 言語：C++17
- GUIフレームワーク：Qt 6.5.3+
- ビルドシステム：CMake 3.20+ / MSVC
- OCR推論：ONNX Runtime 1.18.1 CPU
- 画像処理：OpenCV 4.x
- JSON解析：nlohmann/json
- Zip圧縮・解凍：minizip
- WindowsシステムAPI：Win32 API、DWM、低レベルキーボードフック
- コンパイラ：MSVC2019 / MSVC2022

## プライバシーとセキュリティについて
1. スクリーンショット処理、ステッカー描画、OCR認識はすべてローカル実行。**スクリーンショットや認識テキストが自動でインターネットへ送信されることはありません。**
2. 自動アップデート機能はバージョン確認と更新ファイル取得の目的のみGitHub/Giteeに接続します。
3. `history`フォルダ内の元画像は平文PNGで保存。パスワード、身分証など機密情報をキャプチャした場合は手動で履歴を削除してください。
4. `.sp1`、`index.dat` はXOR+base64による簡易難読化であり**強固な暗号化ではありません。機密データを保存しないでください。**
5. 設定画面からスクリーンショット履歴保存を無効化可能。

## 既知の制限事項
- 現在Windows 10 / 11 x64のみ対応。Linux、macOSには対応していません。
- OCRはCPUで処理するため認識速度はCPU性能に依存します。
- OCRモデルファイルはサイズが大きく手動で配置する必要があります。
- 混合DPIマルチモニタ環境は実機でのテストを推奨。特殊なハードウェア環境では互換性の問題が生じる可能性があります。

### リリース前リソース前処理

リリース用パッケージを作成する前に、**必ず**下記のリソースコンパイルスクリプトを実行してください。

```
# 多言語ロケールリソースのコンパイル
python tools\compile_locales.py
# 画像リソースのパッキング
python tools\pack_img_res.py
```

### 更新パッケージ選択ロジック（自動アップデーターのルール）

| ローカルにインストール済みバージョン | ダウンロードするパッケージ種別 |
| --- | --- |
| V1.0.1（前回正式リリース版） | 差分パッケージ（最もサイズが小さく、数MB程度） |
| V1.0.0（ベースライン版） | フルパッケージ（1.0.0ベースラインとの差分を計算） |
| その他の古いバージョン | フルパッケージ（1.0.0ベースラインとの差分を計算） |
| 未インストール | **最初にV1.0.0ベースライン版をインストールする必要があります** |
 
> ⚠️ `build_release_1.0.0` はグローバルなベースラインディレクトリです。**1回だけ生成し、永久に保持してください。削除・変更しないでください**。以降のすべての差分更新はこのベースラインに依存します。

### make_release.py スクリプト使用例

```
# 1.【実行は1回のみ】ベースラインバージョン1.0.0を作成
python tools/make_release.py --version 1.0.0 --no-build

# 2.1.0.1をリリース（ベースラインは1.0.0固定、旧版 build_release_1.0.0 と比較）
python tools/make_release.py --version 1.0.1 --make-update --old build_release_1.0.0 --base-dir build_release_1.0.0 --no-build

# 3.1.0.2をリリース（ベースラインは1.0.0固定、旧版 build_release_1.0.1 と比較）
python tools/make_release.py --version 1.0.2 --make-update --old build_release_1.0.1 --base-dir build_release_1.0.0 --no-build

# 4.1.0.3をリリース（ベースラインは1.0.0固定、旧版 build_release_1.0.2 と比較）
python tools/make_release.py --version 1.0.3 --make-update --old build_release_1.0.2 --base-dir build_release_1.0.0 --no-build

# よく使うコマンド
# 完全ワークフロー：コンパイルビルド + リリース成果物収集
python tools/make_release.py --version 1.0.1

# ビルド実行 + フルパッケージ・差分更新パッケージを生成
python tools/make_release.py --version 1.0.1 --make-update --old build_release_1.0.0

# バイナリは既にコンパイル済み、パッケージ作成のみ実行、ビルド手順をスキップ
python tools/make_release.py --version 1.0.1 --no-build

# 更新ログと強制更新フラグを有効にして更新パッケージを生成
python tools/make_release.py --version 1.0.1 --make-update --old build_release_1.0.0 --update-log "1.UIを最適化\n2.既知の不具合を修正" --force-update
```

### パラメータ簡易リファレンス

- `--version x.x.x`：リリース対象のバージョン番号を指定
- `--no-build`：C++コンパイルをスキップ、パッケージ作成のみ実行（バイナリが既にビルド済みの場合に使用）
- `--make-update`：差分パッケージ生成を有効。フルパッケージと差分パッチの両方を出力
- `--old <dir>`：前回正式リリースのディレクトリ。ファイル比較を行い差分パッチを作成するために使用
- `--base-dir <dir>`：グローバルベースラインディレクトリ。常に `build_release_1.0.0` を指定
- `--update-log`：当該バージョンのリリースノート。改行には `\n` を使用
- `--force-update`：強制更新フラグを有効。クライアント側でアップグレードを強制実行

 
> ビルド成果物は `build_release_<version>` 配下に出力されます。フォルダ内のzipアーカイブをGitHub Releasesへアップロードしてください。
