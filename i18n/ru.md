# SnipOCR
> Высокопроизводительная утилита для скриншотов, наклеек рабочего стола и офлайн‑OCR для Windows, написана на C++17 / Qt6.

SnipOCR — это открытая универсальная настольная утилита для Windows 10 / 11 x64. Она объединяет высокопроизводительный захват экрана, плавающие наклейки‑изображения на рабочем столе, аннотации к изображениям, многоязычную офлайн‑распознавание OCR, отложенный циклический скриншот и систему автоматических обновлений.

**Поддерживаемые языки интерфейса: упрощённый китайский, традиционный китайский, английский, японский, корейский, немецкий, французский, русский. Распознавание текста OCR работает для всех перечисленных языков.**

Все операции обработки изображений и распознавания текста выполняются **локально на вашем устройстве. Скриншоты никогда не отправляются в облако, ваша конфиденциальность защищена.**
Подходит для извлечения офисных материалов, помощи при чтении и переводе, извлечения текста из веб‑документов, захвата ресурсов для разработчиков, аннотирования скриншотов для учебных демонстраций и многих других сценариев.

Разработано с использованием нативных API Windows и Qt6. Поддерживает многомониторные конфигурации с высоким DPI, светлую и тёмную темы, полностью интернационализированный многоязычный интерфейс, может работать в фоновом режиме из системного трея.

## Возможности
### 📷 Модуль скриншотов
- **Горячая клавиша для скриншота**: реализована через низкоуровневый хук клавиатуры Windows `WH_KEYBOARD_LL`. Запуск захвата экрана одной комбинацией клавиш независимо от активного окна.
- **Свободный выбор области**: перетащите мышь для рисования прямоугольника выделения с 8 точками изменения размера. Точная подстройка стрелками: шаг 1 пиксель, `Shift + стрелка` для смещения на 10 пикселей для точного выделения пикселей.
- **Прилипание к краям окон**: идея взята из Snipaste. Границы выделения автоматически прилипают к границам окон (порог по умолчанию 8 пикселей) для быстрого захвата всего окна.
- **Точное обнаружение окон и элементов управления**: использует `WindowFromPoint` + `RealChildWindowFromPoint` для определения дочерних элементов: кнопок, полей ввода, панелей инструментов и прямого выделения их областей.
- **Получение реальных границ окна через DWM**: вызывает `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` для исключения теней окна и получения фактических размеров отображаемого окна.
- **Пиксельная лупа**: наложение лупы в режиме захвата, отображает значения цветов RGB / HEX и координаты экрана. Переключение формата цвета для пипетки и проверки пикселей.
- **Метка размеров выделения**: метка размера `W × H` с закруглённым синим фоном рядом с областью выделения. Цвет текста автоматически подстраивается под светлую / тёмную тему.
- **Панель инструментов скриншота**: нижняя панель появляется после выделения области. Поддерживает закрепление наклейки, распознавание OCR, распознавание QR‑кода, копирование изображения, сохранение в PNG и отмену операции.

### 🖼️ Наклейки рабочего стола и аннотации
- **Плавающие наклейки**: закрепляйте сделанные скриншоты прямо на экране в исходном положении, стиль как у Snipaste. Полная поддержка соотношения пикселей DPR для предотвращения размытия на высокоразрешительных дисплеях.
- **Полный набор инструментов аннотаций**: правый клик открывает панель рисования: выделение, перо, стрелка, прямоугольник, эллипс, выделение цветом, мозаика, текстовая заметка, ластик.
- **Преобразование изображений**: наклейки поддерживают масштабирование от 20 % до 500 %; поворот на 90° по часовой и против часовой стрелки, горизонтальное и вертикальное отражение. Все операции выполняются с исходным физическим разрешением изображения без потери качества.
- **Впекание аннотаций при экспорте**: объединяет все нарисованные аннотации с исходным изображением и экспортирует готовый PNG с сохранением исходного разрешения.
- **Панель пипетки цвета экрана**: независимая реализация пипетки для взятия цвета любого пикселя экрана, совместима с многоязычным интерфейсом.
- **Переключение тени окна‑наклейки**: включение и отключение эффекта тени для окон‑наклеек под визуальный стиль скруглённых углов нативного Windows 11.
- **Управление группами наклеек**: несколько групп наклеек (группа по умолчанию + пользовательские группы). При переключении группы скрываются наклейки текущей группы и восстанавливается расположение наклеек другой группы.
- **Постоянная история скриншотов**: исходные скриншоты сохраняются в формате PNG в локальной папке `history`. Положение, масштаб и состояние аннотаций наклеек хранятся в файлах `.sp1` с лёгкой обфускацией XOR+Base64 (не сильное шифрование, только защита от случайного изменения).
- **Автоматическое восстановление наклеек при перезапуске**: при повторном запуске приложения восстанавливаются все плавающие наклейки с последними положениями, масштабом и принадлежностью к группам.

### 🔍 Офлайн‑распознавание текста OCR
- **Параллельная загрузка нескольких моделей**: одновременная загрузка нескольких моделей распознавания. Поддерживает смешанный китайско‑английский текст, корейский, русский кириллический и латинский шрифты.
- **Автоматическое определение языка**: алгоритм анализирует долю символов на изображении и автоматически переключает соответствующую модель OCR, ручной выбор языка не требуется.
- **Вычисления ONNX Runtime на CPU**: работает исключительно на процессоре. **Дискретная видеокарта не нужна**, программа работает на обычных ноутбуках.
- **Неблокирующий фоновый поток**: задачи OCR выполняются в независимом рабочем потоке QThread, интерфейс остаётся отзывчивым во время распознавания.
- **Диалог результатов распознавания**: редактируемое окно вывода OCR. Поддерживает копирование в буфер обмена одним кликом и сохранение текста в локальный файл.

### ⏱️ Отложенный скриншот
- **Отложенный и циклический захват**: установка задержки от 1 до 10 секунд, настройка количества повторных скриншотов для пакетного автоматического сохранения.
- **Системное уведомление toast**: нативное всплывающее окно Windows после завершения серии снимков, отображает путь сохранения и количество скриншотов. Клик по уведомлению копирует путь к файлу.

### 🔄 Система автоматических обновлений
- **Проверка версии**: автоматическая проверка версии при запуске; ручная проверка доступна в панели настроек.
- **Механизм дельта‑обновлений**: генерирует полные релиз‑пакеты и дифференциальные патчи на основе базовой версии. Загружаются только изменённые файлы для уменьшения объёма скачивания.
- **Маршрутизация по двум источникам**: источник загрузки Gitee для пользователей материкового Китая, GitHub Releases для зарубежных пользователей для решения различий сетевого доступа.
- **Независимый исполняемый файл обновителя**: `updater.exe` построен на чистом Win32 API + minizip, без зависимостей от Qt.
- **Сохранение конфигурации и пользовательских данных**: резервное копирование файла настроек `.config_settings.json` во время обновления. Восстановление параметров после обновления; горячие клавиши, темы и настройки групп наклеек сохраняются.
- **Рабочий процесс перезапуска после обновления**: после завершения обновления вызывается `ShellExecuteExW` для запуска новой программы с аргументом `--restart`, обход мьютекса единственного экземпляра для корректного перезапуска.

### ⚙️ Интеграция с системой
- **Фоновая служба системного трея**: сворачивание в трей. Контекстное меню трея: скриншот, OCR, отложенный захват, группы наклеек, очистить историю, параметры, перезапуск приложения, выход.
- **Интернационализация приложения**: встроенные интерфейсы упрощённого китайского `zh_CN` и английского `en_US`. Смена языка во время работы. Встроенные диалоги Qt также локализованы.
- **Адаптация светлой‑тёмной темы**: следование системной теме или ручное переключение. Маски‑наложения, разделители меню и тени окон подстраиваются под выбранную тему.
- **Мьютекс единственного экземпляра**: глобальный мьютекс предотвращает многократный запуск программы. Специальный аргумент пропускает проверку мьютекса при перезапуске после обновления.
- **Совместимость с UTF‑8‑путями на китайском языке**: обход ошибки нативного API Qt, который может возвращать пустые значения для путей Windows UTF‑8 с китайскими символами.

## Загрузка и установка
1. Получите последнюю версию из раздела [Releases](https://github.com/xuhuandeshilinghun/snip‑ocr/releases): `SnipOCR‑<version>‑win64.zip`
2. Распакуйте архив в любую локальную папку. Портативная программа, установщик не требуется.
3. Скачайте отдельный архив с моделью OCR и распакуйте его в подпапку `model/` программы.
4. Запустите `SnipOCR.exe`.

> **Обязательное системное требование: Windows 10 / Windows 11 x64**
> Файлы моделей OCR имеют большой размер и не включены в основной архив программы.
> Не распаковывайте в системно‑защищённые каталоги, такие как `C:\Windows` или `Program Files`, чтобы избежать проблем с правами чтения‑записи.

## Стек технологий
- Язык: C++17
- Фреймворк GUI: Qt 6.5.3+
- Система сборки: CMake 3.20+ / MSVC
- Вычисления OCR: ONNX Runtime 1.18.1 CPU
- Обработка изображений: OpenCV 4.x
- Парсинг JSON: nlohmann/json
- Сжатие / распаковка Zip: minizip
- Системные интерфейсы Windows: Win32 API, DWM, низкоуровневый хук клавиатуры
- Компилятор: MSVC2019 / MSVC2022

## Примечания о конфиденциальности и безопасности
1. Обработка скриншотов, рендеринг наклеек и распознавание OCR полностью выполняются локально. Программа **никогда не отправляет скриншоты или распознанный текст в интернет автоматически.**
2. Функция автоматического обновления подключается к серверам GitHub / Gitee исключительно для проверки версии и загрузки пакетов обновления.
3. Исходные скриншоты сохраняются в виде обычного PNG в папке `history`. Вручную очищайте папку истории, если вы захватывали пароли, документы удостоверения личности и другую конфиденциальную информацию.
4. Файлы `.sp1` и `index.dat` используют простую обфускацию XOR+base64 **это не безопасное шифрование. Не храните в этих файлах высококонфиденциальные данные.**
5. В настройках программы можно отключить сохранение истории скриншотов.

## Известные ограничения
- На данный момент поддерживается только Windows 10 / 11 x64. Поддержка Linux и macOS отсутствует.
- OCR работает на процессоре; скорость распознавания зависит от производительности вашего CPU.
- Файлы моделей OCR имеют большой размер, их нужно скачивать и размещать вручную.
- Конфигурации многомониторных систем со смешанным DPI рекомендуется тестировать в реальных условиях использования; при редких специфических аппаратных конфигурациях могут появляться проблемы совместимости.

### Логика выбора пакета обновления (правила автообновителя)

| Установленная локальная версия | Тип загружаемого пакета |
| --- | --- |
| V1.0.1 (предыдущий официальный релиз) | Дельта‑пакет (минимальный размер, всего несколько МБ) |
| V1.0.0 (базовая версия) | Полный пакет (расчет отличий относительно базовой версии 1.0.0) |
| Другие старые версии | Полный пакет (расчет отличий относительно базовой версии 1.0.0) |
| Не установлено | **Сначала необходимо установить базовую версию V1.0.0** |

> ⚠️ `build_release_1.0.0` — глобальный базовый каталог. **Создайте его один раз, храните постоянно, не удаляйте и не изменяйте**. Все последующие дельта‑обновления зависят от этой базы.

### Примеры работы со скриптом make_release.py

```
# 1.【Выполнить один раз】Создать базовую версию 1.0.0
python tools/make_release.py --version 1.0.0 --no-build

# 2.Выпуск версии 1.0.1 (база фиксирована на 1.0.0, сравнение с старым build_release_1.0.0)
python tools/make_release.py --version 1.0.1 --make-update --old build_release_1.0.0 --base-dir build_release_1.0.0 --no-build

# 3.Выпуск версии 1.0.2 (база фиксирована на 1.0.0, сравнение с старым build_release_1.0.1)
python tools/make_release.py --version 1.0.2 --make-update --old build_release_1.0.1 --base-dir build_release_1.0.0 --no-build

# 4.Выпуск версии 1.0.3 (база фиксирована на 1.0.0, сравнение с старым build_release_1.0.2)
python tools/make_release.py --version 1.0.3 --make-update --old build_release_1.0.2 --base-dir build_release_1.0.0 --no-build

# Часто используемые команды
# Полный цикл: компиляция сборки + сборка артефактов релиза
python tools/make_release.py --version 1.0.1

# Сборка + генерация полного и дельта‑пакета обновления
python tools/make_release.py --version 1.0.1 --make-update --old build_release_1.0.0

# Бинарные файлы уже скомпилированы, только упаковка, пропустить шаг сборки
python tools/make_release.py --version 1.0.1 --no-build

# Генерация пакетов обновления с примечаниями к релизу и флагом принудительного обновления
python tools/make_release.py --version 1.0.1 --make-update --old build_release_1.0.0 --update-log "1.Оптимизация интерфейса\n2.Исправление известных ошибок" --force-update
```

### Краткая справка по параметрам

- `--version x.x.x`: задать номер целевой версии релиза
- `--no-build`: пропустить компиляцию C++, выполнить только упаковку (используйте при готовых бинарных файлах)
- `--make-update`: включить генерацию дельта‑пакета; выводит как полный пакет, так и дельта‑патч
- `--old <dir>`: каталог предыдущего официального релиза, используется для сравнения файлов при создании дельта‑патча
- `--base-dir <dir>`: глобальный базовый каталог, всегда указывайте `build_release_1.0.0`
- `--update-log`: примечания к данному релизу; для переноса строк используйте `\n`
- `--force-update`: включить флаг принудительного обновления; клиент будет производить принудительное обновление

> Результаты сборки помещаются в каталог `build_release_<version>`. Загрузите ZIP‑архивы из этого каталога на GitHub Releases.
